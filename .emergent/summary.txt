<product_requirements>
The application is a warehouse and production management system for a meat processing facility. The primary goal is to digitize and manage the entire production lifecycle, from raw material consumption to finished goods inventory.

**Core problem:** To accurately track inventory and guide operators through complex, multi-step production recipes for various meat products like Basturma, Sudzhuk, and others.

**Implemented Functionality:**
-   **Production Module:** Users can create production batches based on recipes. The system deducts raw meat at the start, deducts all spices when a mix is made, and handles specific steps like Salting.
-   **Data Integrity:** All production recipes in the database have been corrected to match the user's official specifications, which were provided via images.
-   **Packaging Module (Skeleton):** A new module for managing the packaging of finished goods has been initiated. Database tables and API endpoints have been created. The database now contains 19 detailed packaging recipes (e.g., Basturma 50g vacuum) with their corresponding material requirements.
-   **Nomenclature Normalization:** Product names have been standardized (e.g., Суджук for the unpackaged product and Суджук ваговий for the packaged version) to support the new packaging logic.

<current_work>
The most recent task was a detailed discussion to define the accounting logic for sausage casings (), a critical material for products like Суджук and Махан. The engineer initially proposed several complex tracking models, including tracking by bundle (штуки), by length (метри), and a hybrid part-number based system.

After consulting with the production team, the user rejected these in favor of a more practical, weight-based approach. The agreed-upon logic is as follows:
1.  **Receiving:** Casings are received in bundles but are recorded in inventory by weight (kg).
2.  **Usage:** When an operator starts the stuffing process, they take a bundle, weigh it, and input the initial weight (e.g., 1.8 kg) into the app.
3.  **Completion:** After using the required amount of casing, the operator weighs the remaining portion of the bundle and inputs the final weight (e.g., 0.3 kg).
4.  **System Action:** The application calculates the difference (1.8 - 0.3 = 1.5 kg) and automatically deducts that amount from the inventory.

The engineer's last action was to formalize this logic in a markdown file and outline the implementation steps required in the backend and frontend. The work is paused right before starting the implementation of this new, user-approved casing logic.
</current_work>
